# 말풍선 공방 — 림버스 컴퍼니 UI 템플릿 구현 명세서

**상태:** 구현 전 설계안\
**대상:** 말풍선 공방 PC 웹 / 모바일 PWA\
**참고 자료:** 사용자 제공 림버스 컴퍼니 스크린샷 4장, 말풍선 공방 인수인계 문서(2026-10-25 갱신)

## 1. 프로젝트 개요

### 1.1 목적

림버스 컴퍼니의 UI 디자인을 참고한 8종의 편집형 템플릿을 말풍선 공방의 게임 UI 카테고리에 추가한다.

사용자는 게임 UI를 직접 제작할 필요 없이 템플릿을 불러온 뒤 캐릭터 이미지, 배경, 대사, 수치, 아이콘을 교체하여 만화나 패러디 이미지를 제작할 수 있어야 한다.

**핵심 원칙**

1. 배경과 장식은 유지하면서 텍스트와 이미지를 개별적으로 편집한다.
2. 템플릿 전체 이동·복제와 내부 항목 편집을 구분한다.
3. 기존 말풍선·게임 UI·레이어 시스템을 훼손하지 않는다.
4. 모든 템플릿은 PNG 및 프로젝트 저장·복원을 지원한다.
5. PC와 모바일의 편집 결과가 동일해야 한다.
6. 실제 게임 시스템을 구현하지 않고 화면 제작 도구로 제공한다.

### 1.2 템플릿 목록

| ID    | 템플릿       | 주요 형태         |
| ----- | --------- | ------------- |
| LC-01 | 스토리 대화창   | 일반/내레이션/특수 화자 |
| LC-02 | 선택지 이벤트   | 선택지 2\~4개     |
| LC-03 | 인격 상세 카드  | 이미지·능력치·스킬    |
| LC-04 | 전투 결과·통계창 | 결과·피해량·그래프    |
| LC-05 | E.G.O 기프트 | 획득·합성         |
| LC-06 | 추출 결과     | 단일·10회·획득 연출  |
| LC-07 | 전투 상태·스킬  | 상태이상·합·스킬 정보  |
| LC-08 | 관찰 일지     | 기록·문서·환상체 정보  |

### 1.3 메뉴 배치

기존 **게임 UI → 림버스 컴퍼니**에 전용 템플릿 목록을 추가한다.

기존 게임 카테고리의 프리셋 번호와 에셋 ID는 변경하지 않는다.

림버스 하위에서는 8개 템플릿을 카드 형태로 제공하고, 각 카드 선택 시 간단한 미리보기와 적용 버튼을 표시한다.

## 2. 공통 디자인 규격

### 2.1 기본 색상

| 항목     | 권장 색상     | 용도          |
| ------ | --------- | ----------- |
| 배경     | `#10100F` | 기본 어두운 배경   |
| 패널     | `#24201C` | 금속·목재 계열 패널 |
| 외곽선    | `#8A623C` | 황동 프레임      |
| 보조 테두리 | `#B48B56` | 강조 장식       |
| 기본 문자  | `#E5D5BA` | 밝은 아이보리 텍스트 |
| 강조 문자  | `#D9A347` | 선택 및 중요 수치  |
| 위험 표시  | `#A82E32` | 붉은색 경고      |
| 비활성    | `#5F5850` | 선택 불가 상태    |

위 수치는 **시안 제작을 위한 임시 팔레트**다. 실제 구현 전 첨부 스크린샷과 확대 비교하여 조정한다.

### 2.2 프레임 구성

- 두께가 다른 이중 테두리
- 잘린 모서리 또는 팔각형 프레임
- 비대칭 금속 장식과 리벳
- 어두운 반투명 내부 패널
- 붉은색 강조 배경
- 오래된 기계·문서 느낌의 텍스처
- 금색 강조선과 거친 표면 효과

반복되는 프레임과 버튼은 공통 렌더러로 제작한다. 각 템플릿에 별도의 동일한 PNG를 중복 보관하지 않는다.

### 2.3 해상도

- 기본 가로 작업 기준: 1280×720(16:9)
- 사용자 제공 참고 스크린샷: 약 1280×591의 잘린 화면
- 가로 UI는 비율을 유지하고 남는 영역을 배경 또는 투명 여백으로 처리
- 세로 웹툰 캔버스에는 원본 가로 비율을 유지한 상태로 삽입
- 텍스트는 가능한 경우 Canvas 기반으로 고해상도 렌더링
- 작은 아이콘의 계단 현상과 장식선 두께를 출력 배율별 검수

화면 크기가 변하더라도 패널의 코너 장식과 글자 비율이 비정상적으로 늘어나지 않도록 한다.

## 3. 기존 말풍선 공방과 통합하는 방법

### 3.1 내부 데이터 구조

기존 `gameui` 객체와 `gamePreset` 계열의 저장·렌더링 구조를 우선 재사용한다.

현재 인수인계에 명일방주 프리셋 등 다른 게임 UI가 이미 기록되어 있으므로, 실제 최신 소스의 프리셋 번호 점유 현황을 먼저 확인한다.

**새 림버스 UI의 가상 데이터 구조(설계상 명칭)**

- `templateId`: LC-01\~LC-08
- `schemaVersion`: 림버스 UI 데이터 버전
- `variant`: 템플릿 세부 형태
- `geometry`: 위치·너비·높이·회전
- `visible`: 템플릿 표시 여부
- `background`: 배경 데이터
- `imageSlots`: 사용자 삽입 이미지 목록
- `textSlots`: 편집 가능한 텍스트 목록
- `statFields`: 능력치 및 수치
- `styleOverrides`: 색상·불투명도·장식 설정
- `slotVisibility`: 내부 요소 표시 여부

이는 신규 파일 포맷을 확정한 것이 아니다. 실제 저장 필드명은 최신 원본과 호환되도록 조정한다.

### 3.2 편집 방식

**1단계: 템플릿 전체 선택**

- 단일 클릭: 전체 선택
- 드래그: 전체 이동
- 크기 핸들: 전체 크기 변경
- 회전 핸들: 전체 회전
- 복제: 내부 데이터를 포함해 독립 복제
- 삭제: 선택된 템플릿 제거

**2단계: 내부 요소 편집**

- 텍스트 더블클릭: 해당 텍스트 편집창
- 이미지 더블클릭: 이미지 교체·위치·확대 편집
- 수치 더블클릭: 수치 입력
- 세부 설정: 내부 요소 표시·숨김, 색상 변경

단일 클릭만으로 텍스트 편집창이 열리지 않도록 한다.

모바일에서는 더블탭 편집을 사용하며, 더블탭 직후 발생하는 후속 클릭이 다른 버튼을 실행하지 않도록 기존 보호 로직과 연결한다.

### 3.3 레이어 구성

권장 기본 레이어 순서:

1. 배경
2. 배경 보정·어두운 오버레이
3. 캐릭터·일러스트
4. 기본 UI 패널
5. 이미지 슬롯 및 아이콘
6. 텍스트·수치
7. 선택 효과·강조 장식
8. 최상단 전경 장식

기본적으로 하나의 림버스 템플릿을 **논리적인 부모 객체 하나**로 관리하고, 내부 구성요소는 자식 슬롯으로 처리한다.

내부 레이어 표시·숨김은 전용 편집 패널에서 제공한다. 기존 레이어 목록에 계층형 트리 표시를 추가하는 기능은 별도 검토한다.

기존 다중선택 그룹화가 독립 이미지 레이어와 모든 UI 객체의 혼합 그룹화를 완전히 지원하는 것은 아니므로, 처음부터 각각을 외부 레이어로 분리하는 방식은 사용하지 않는다.

### 3.4 공통 UI 편집 기능

- 배경 이미지 교체
- 이미지 슬롯별 비율 유지, 채우기, 맞춤, 크롭
- 텍스트 내용·글꼴·색상·크기·정렬 변경
- 표시·숨김 전환
- 프레임 색상 변경(허용된 부분)
- 불투명도 조절
- 전체 이동·회전·크기 변경
- 기본값으로 초기화
- Undo/Redo
- 복제 및 프로젝트 저장

기존 글꼴 관리 기능을 재사용하고, 필요한 서체는 재배포 가능 여부를 확인한 뒤 추가한다.

### 3.5 공통 편집 보호

- 단순 선택이나 편집창 열기만으로 프로젝트를 변경하지 않는다.
- 입력·토글 등 하나의 논리적 작업은 Undo 1회로 복구 가능해야 한다.
- 드래그는 이동 시작 상태를 기준으로 처리한다.
- 모바일 핀치 시작 시 이전 드래그의 불완전한 변경을 취소한다.
- 내부 이미지 교체는 다른 슬롯의 사용자 이미지를 변경하지 않는다.
- 프리셋 형태를 전환해도 사용자 입력 데이터는 보존한다.
- 새 객체가 기존 프로젝트에 자동 삽입되는 일은 없어야 한다.

## 4. 개별 템플릿 상세 명세

### LC-01. 스토리 대화창

**목적:** 스토리 장면, 캐릭터 대사 및 내레이션 제작.

**형태 A — 일반 대화**

- 화면 하단의 어두운 반투명 대화 영역
- 화자 이름표
- 대사 텍스트
- 진행 표시 삼각형
- 캐릭터 이미지 슬롯
- 배경 이미지 슬롯

**형태 B — 내레이션**

- 이름표 없는 텍스트 형태
- 좌측 또는 중앙 정렬
- 배경을 어둡게 만드는 선택 옵션
- 진행 표시의 표시·숨김

**형태 C — 특수 화자**

- 관리자·시스템·정체불명 화자 등 연출
- 전용 이름표 스타일
- 이름 대신 기호나 식별자 사용 가능
- 붉은색·금색 강조 옵션
- 인물 이미지를 표시하지 않는 형태 지원

**편집 항목**

- 화자명
- 본문 대사
- 대사 줄 간격
- 텍스트 박스 위치·너비
- 이름표 색상 및 크기
- 캐릭터 일러스트(좌·중·우 슬롯)
- 캐릭터 크기·위치·불투명도
- 배경
- 대화창 배경 농도
- 진행 표시 유무

**필수 동작**

- 대화창만 투명 PNG로 추출할 수 있어야 한다.
- 대화창만 적용하는 모드와 배경·캐릭터 포함 모드를 제공한다.
- 화자 종류를 변경해도 이미 입력된 이름과 대사는 보존한다.
- 일반↔내레이션 전환 시 이름표의 표시 상태만 변경하고 입력값은 삭제하지 않는다.
- 배경·인물·대화창의 렌더 순서를 유지한다.

**완료 기준:** 사용자 이미지를 넣고 이름과 대사를 변경해 스토리 스크린샷 형태의 PNG를 제작할 수 있다.

### LC-02. 선택지 이벤트

**목적:** 게임 속 이벤트 선택, 환상체 이벤트, 의사결정 장면을 만화로 제작.

**선택지 형태**

- 2개 선택지
- 3개 선택지
- 4개 선택지

**구성**

- 이벤트 제목
- 설명 텍스트
- 사건 이미지 슬롯
- 선택지 버튼 2\~4개
- 선택지 번호 또는 장식
- 선택 강조 프레임
- 하단 결과·안내 텍스트(선택)

**편집 항목**

- 선택지 개수
- 각 선택지의 텍스트
- 선택지별 줄바꿈
- 선택 상태: 없음 / 1 / 2 / 3 / 4
- 선택지 활성·비활성 표시
- 강조 색상
- 이미지·배경
- 결과 안내 문구

**동작 정의**

- 선택지 개수를 변경하면 UI가 자동 재배치된다.
- 4개에서 2개로 바꿔도 나머지 선택지의 텍스트는 보관한다.
- 선택된 버튼은 다른 버튼보다 밝은 강조 효과를 가진다.
- 한 선택지를 삭제하거나 숨겨도 나머지 선택지의 순서가 꼬이지 않아야 한다.
- 선택지 클릭은 편집기에서 강조 상태를 변경하는 기능이지 실제 게임 선택을 실행하는 기능이 아니다.

**확장 기능**

장면 복제를 통해 선택 전 → 선택 후 → 결과 화면으로 이어지는 만화 장면을 만들 수 있도록 한다. 실제 분기형 게임 엔진은 구현 대상에서 제외한다.

### LC-03. 인격 상세 카드

**목적:** 캐릭터 소개 카드, 패러디 인격 카드, 커스텀 인격 프로필 제작.

**형태**

- 인격 카드 중심형
- 인격 상세 정보형

**구성**

- 캐릭터 일러스트
- 인격명
- 소속 및 부제
- 레벨
- 희귀도(0 / 00 / 000)
- 캐릭터 아이콘
- 체력·정신력 등의 능력치
- 공격 유형·내성
- 스킬 이름·설명
- 패시브 설명
- 장식 프레임

**편집 항목**

- 캐릭터 이미지
- 인격 이름
- 소속명
- 레벨(표시용 정수)
- 희귀도
- 스킬 1·2·3 이름 및 설명
- 패시브 이름 및 설명
- 능력치 수치
- 속성 아이콘
- 카드 테두리 강조

**필수 동작**

- 이미지를 교체해도 인격명과 스탯은 보존한다.
- 희귀도 선택에 따라 장식만 자동 변경할 수 있다.
- 스킬 설명 길이에 맞춰 내부 글자 크기나 영역을 조정한다.
- 수치는 기본적으로 사용자 직접 입력이며, 실제 게임 밸런스 계산은 수행하지 않는다.
- 카드 목록형과 상세형이 공유하는 기본 정보는 같은 필드에서 관리한다.

**완료 기준:** 기존 인격과 무관한 사용자 제작 캐릭터를 인격 카드 형식으로 출력할 수 있다.

### LC-04. 전투 결과·통계창

**목적:** 전투 승패, 캐릭터별 실적, 피해량 비교 화면 제작.

**형태**

- 전투 결과 요약
- 캐릭터별 통계 비교

**구성**

- 결과 제목
- 승리·패배 등 상태 문구
- 캐릭터 목록
- 피해량·기여도 수치
- 가로형 막대그래프
- 총합 및 주요 지표
- 확인 버튼 장식

**편집 항목**

- 결과 제목
- 결과 상태
- 캐릭터 이름·이미지
- 캐릭터 수(기본 1\~12명)
- 피해량
- 받은 피해량
- 처치 수
- 그래프 색상
- 그래프 정렬 순서
- 표시할 통계 종류

**그래프 처리**

- 수치를 입력하면 그래프 길이를 자동 계산한다.
- 최댓값을 기준으로 상대 비율을 표시한다.
- 모든 값이 0이면 막대 길이를 0으로 표시한다.
- 총합은 자동 계산 또는 독립 입력 중 선택 가능하게 한다.
- 그래프와 실제 표시 수치가 서로 다르게 저장되는 문제를 방지한다.

**완료 기준:** 사용자 캐릭터와 임의의 수치로 전투 결과·기여도 순위 화면을 제작할 수 있다.

### LC-05. E.G.O 기프트 획득·합성창

**목적:** 아이템 획득, 기프트 소개, 아이템 합성 연출 제작.

**형태 A — 기프트 획득**

- 획득 제목
- 아이템 아이콘
- 기프트 이름
- 등급
- 효과 설명
- 강조 장식
- 확인 버튼

**형태 B — 기프트 합성**

- 재료 슬롯
- 합성 기호·연결선
- 결과 슬롯
- 아이템 이름과 설명
- 합성 실행·결과 버튼 장식

**편집 항목**

- 아이템 이름
- 아이콘
- 등급(I\~V 표시 프리셋)
- 설명
- 재료 개수
- 각 재료 아이콘
- 결과 아이콘
- 합성 제목
- 성공·실패·미확정 표시
- 배경 강조 색상

**필수 동작**

- 재료 슬롯은 1\~3개를 기본 지원한다.
- 재료 개수가 바뀌면 자동 재배치한다.
- 아이콘별 교체·확대·크롭을 지원한다.
- 획득형과 합성형을 별도 템플릿 변형으로 관리한다.
- 기프트 명칭, 등급, 효과 등은 실제 게임 데이터와 독립적인 사용자 입력값으로 처리한다.

**제외 범위:** 실제 기프트 조합법 데이터베이스와 성공 확률 계산.

### LC-06. 추출 결과·획득 연출

**목적:** 인격 또는 E.G.O 추출 결과를 패러디 카드와 획득 화면으로 제작.

**형태**

- 단일 추출 결과
- 10회 추출 결과
- 획득 강조 화면

**구성**

- 추출 결과 제목
- 추출 카드 슬롯
- 카드 일러스트
- 인격명 또는 E.G.O명
- 희귀도
- 중복 획득 표시
- 강조 배경
- 확인·다시 추출 버튼 장식

**편집 항목**

- 카드 개수
- 각 카드 이미지
- 각 카드 이름
- 희귀도(0 / 00 / 000)
- 카드 테두리 스타일
- 중복 표시 여부
- 획득 문구
- 배경
- 강조 이펙트 농도

**획득 연출 설계**

첫 버전에서는 다음과 같은 정적인 화면 프리셋으로 제작한다.

1. 추출 시작
2. 카드 등장
3. 희귀도 강조
4. 최종 획득 결과

각 장면을 복제해 만화 컷으로 활용할 수 있어야 한다.

실제 시간 기반 애니메이션은 현재 편집기의 타임라인 구현 여부를 검토한 뒤 별도 확장한다.

**필수 동작**

- 단일↔10회 전환 시 카드 데이터 보존
- 10회 결과에서 각 카드 독립 편집
- 희귀도별 테두리 변경
- 카드 순서 변경
- 새로고침 후 편집 내용 복원

**완료 기준:** 직접 넣은 10개 이미지로 추출 결과 화면을 제작하고 PNG로 저장할 수 있다.

### LC-07. 전투 상태·스킬 설명창

**목적:** 전투 상황, 스킬 소개, 상태이상 정보, 합 판정 화면 제작.

**형태**

- 기본 전투 상태 HUD
- 스킬 상세 설명
- 합 비교 화면

**구성**

- 캐릭터 또는 적 아이콘

- 스킬 이름
- 스킬 코인
- 위력 수치

- 스킬명
- 기본 위력

**기존 기능 재사용**

말풍선 공방에 존재하는 범용 상태창과 상태이상 아이콘 체계를 우선 참고한다.

상태이상 아이콘 렌더러와 이미지 로더는 가능한 한 공용화하되, **기존 상태창의 저장값을 림버스 템플릿이 직접 덮어쓰지 않도록 분리**한다.

**동작**

- 체력 수치 변경 시 게이지 길이 변경(사용자 선택)
- 스킬 코인 개수 변경 시 자동 배치
- 상태이상 항목 추가·삭제·순서 변경
- 합 결과 강조색 변경
- 스킬 설명 표시·숨김
- 사용자 임의의 전투 결과 입력

실제 위력 계산기나 게임 전투 시뮬레이터는 포함하지 않는다.

**동작**

## 5. 화면 및 편집 패널 구성

### 5.1 템플릿 선택 패널

메뉴 경로:

`게임 UI → 림버스 컴퍼니 → 템플릿 선택`

각 템플릿 카드에는 다음 요소를 표시한다.

- 썸네일
- 템플릿 이름
- 변형 개수
- 간단한 사용 설명
- 적용 버튼

### 5.2 상세 편집 패널

공통 탭은 다음 4개로 구성한다.

**기본:** 변형 선택, 크기, 위치, 전체 표시 설정\
**텍스트·수치:** 이름, 대사, 스킬, 능력치, 목록 편집\
**이미지:** 슬롯별 이미지 교체, 확대, 크롭, 표시 상태\
**스타일:** 프레임, 색상, 불투명도, 장식 설정

템플릿에 없는 기능은 숨기며 비어 있는 설정 칸을 남기지 않는다.

### 5.3 빠른 편집

PC의 더블클릭과 모바일의 더블탭을 지원한다.

- 이름 → 이름 편집
- 대사 → 대사 편집
- 숫자 → 수치 입력
- 그림 → 이미지 교체·크롭
- 선택지 → 해당 선택지 편집
- 스킬 아이콘 → 아이콘·속성 설정

편집 가능한 항목마다 안정적인 슬롯 ID를 부여한다.

슬롯 위치가 달라졌다는 이유만으로 다른 항목이 선택되거나 편집되어서는 안 된다.

## 6. 저장·레이어·단축키 호환성

### 6.1 프로젝트 저장

- 기존 프로젝트 구조 유지
- 림버스 데이터에 버전 정보 포함
- 구형 프로젝트의 값이 누락된 신규 필드는 안전한 기본값 사용
- 사용자 지정 이미지·폰트·수치·문구 보존
- 템플릿 변형 변경 후 저장·복원
- 페이지 복제 시 하위 데이터 독립 복사
- 알 수 없는 신규 필드 때문에 전체 문서 로드 실패가 발생하지 않도록 처리

### 6.2 단축키

기존 단축키를 새로 정의하거나 가로채지 않는다.

- Ctrl/Cmd+C·V: 기존 클립보드 우선순위 보존
- Ctrl/Cmd+G: 현재 지원하는 그룹화 규칙 유지
- Delete/Backspace: 선택 객체 삭제
- Ctrl/Cmd+Z: Undo
- Ctrl/Cmd+Shift+Z 또는 기존 Redo 경로 유지

입력칸 포커스 상태에서는 텍스트 입력·복사·붙여넣기가 우선한다.

외부에서 복사한 클립보드 이미지는 기존 이미지 삽입 경로를 유지한다.

### 6.3 오브젝트 복제

템플릿 복제 시:

- 새 부모 객체 ID 부여
- 필요한 자식 슬롯 ID 재발급
- 사용자 이미지 데이터 독립 보존
- 텍스트·수치·표시 설정 독립 복사
- 기존 객체와 설정 참조 공유 금지

10회 추출 카드처럼 많은 내부 요소가 있더라도 개별 에디터 오브젝트를 과도하게 생성하지 않도록 한다.

기존 객체 수 상한 및 검증 규칙을 침해하지 않는다.

### 6.4 PNG 출력

- 전체 화면 PNG
- 배경 제외 투명 PNG
- 현재 캔버스 크기 기준 출력
- 출력에서 편집 핸들·슬롯 안내·경고 배지 제거
- 사용자 지정 글꼴 및 이미지 로드 완료 후 출력
- 숨긴 요소는 출력하지 않음
- 썸네일과 최종 출력의 레이아웃 일치

## 7. 구현 구조 제안

기존 원본을 확인한 다음 실제 파일 경로를 확정한다.

가상 모듈 구성:

| 모듈                       | 역할               |
| ------------------------ | ---------------- |
| `gameui-limbus`          | 공통 렌더링 및 템플릿 정의  |
| `gameui-limbus-controls` | 편집 패널과 입력 이벤트    |
| `gameui-limbus-assets`   | 프레임·아이콘·이미지 로더   |
| `gameui-limbus-data`     | 기본 프리셋·검증·데이터 변환 |
| `limbus-ui` 테스트          | 렌더·저장·복원·이벤트 검증  |

예상 위치는 기존 `public/`, `tests/`, `docs/assets/` 체계를 기준으로 하되 실제 소스의 모듈 분할 방식에 맞춘다.

**제약 사항**

- 생성된 `dist/` 파일을 직접 수정하지 않는다.
- 기존 `index.html` 스크립트 로딩 순서와 공유 상태를 확인한다.
- 템플릿 이름을 이유로 기존 데이터의 프리셋 번호를 재배치하지 않는다.
- 기존 배포·호스팅 설정을 변경하지 않는다.
- 폰트·이미지·원본 게임 에셋의 배포 권한을 구분한다.
- 게임 스크린샷은 참고 자료로 사용하고, 공개 배포용 UI 그래픽은 권리 관계를 검토하여 독자 제작한다.

## 9. 검수 기준

### 9.1 공통 기능

- 템플릿 8종 모두 목록에 표시된다.
- 각 템플릿의 변형을 전환할 수 있다.
- 모든 지정 텍스트 슬롯을 편집할 수 있다.
- 지정 이미지 슬롯에 사용자 이미지를 삽입할 수 있다.
- 템플릿 이동·회전·확대·축소가 정상 작동한다.
- 레이어 표시·숨김이 출력까지 반영된다.
- Undo/Redo가 정상 작동한다.
- 복제본을 수정해도 원본은 유지된다.
- 프로젝트 저장·불러오기가 정상이다.
- PNG와 썸네일의 구성이 일치한다.

| 템플릿   | 필수 테스트                |

| LC-07 | 코인 개수 변경, 상태 아이콘 관리   |
| LC-08 | 긴 본문, 페이지 복제·저장·출력    |

### 9.3 회귀 테스트

- 기존 말풍선 연결과 이동 그룹화
- Ctrl+C/V와 외부 클립보드 이미지
- 상태창 및 시스템 메시지
- 명일방주와 다른 게임 UI
- 컷 프레임 선택·잠금·이미지 교체
- 레이어 숨김
- 모바일 더블탭·핀치
- 여러 장의 만화 페이지 복원
- 사용자 지정 글꼴 복원
- PNG 투명 배경 출력

### 9.4 성능 검수

- 텍스트 수정 시 전체 캔버스를 불필요하게 재구성하지 않는다.
- 변경된 슬롯 중심으로 갱신한다.
- 장식·이미지·아이콘을 가능한 범위에서 캐싱한다.
- 고해상도 출력은 화면 미리보기와 구분해 처리한다.
- 10회 추출 및 다수 캐릭터 통계 화면에서 과도한 객체 생성과 입력 지연을 방지한다.
- PC 자동 테스트 통과와 실제 모바일 기기 검증 완료를 구분해 기록한다.

## 10. 최종 완료 조건

**기능 완료**

8종의 림버스 스타일 UI 템플릿을 선택하고, 텍스트와 이미지를 직접 수정한 뒤 프로젝트 저장 및 PNG 출력이 가능한 상태.

**호환성 완료**

기존 말풍선·게임 UI·레이어·복제·그룹화·자동저장·단축키를 훼손하지 않는 상태.

**디자인 완료**

사용자 제공 레퍼런스의 프레임 비율, 색상 구성, 글자 배치, 장식 밀도, 화면 구조를 비교해 주요 차이를 검수한 상태. 공개용 그래픽은 사용 권리가 확인된 리소스 또는 독자 제작 리소스를 사용한다.

**배포 완료**

실제 빌드 및 테스트 통과, 배포된 버전 확인, `AGENTS.md`·`HANDOFF.md`·`CHANGELOG.md`에 변경·검증·미완료 사항 기록.

## 설계상 가장 중요한 판단

이번 명세서에서는 템플릿 전체를 하나의 부모 객체로 관리하면서 내부 이미지·텍스트 슬롯을 개별 편집하는 방식을 채택했어.

이 방식이 좋은 이유는 기존의 그룹화·클립보드·레이어 기능에 미치는 영향을 최소화하면서도 10회 추출처럼 내부 요소가 많은 화면을 처리할 수 있기 때문이야.

또한 스토리 대화창부터 관찰 일지까지 모두 서로 다른 인터페이스처럼 보여도 실제로는 프레임, 이미지 슬롯, 편집 텍스트, 반복 목록이라는 공통 요소로 구성할 수 있어. 공통 기반을 먼저 개발하면 이후 다른 게임 UI 템플릿을 추가할 때도 재사용할 수 있겠지.

남은 가장 큰 과제는 시각적 재현의 정확도야. 지금의 문서는 개발 구조와 동작 조건을 정한 것이고, 각 버튼·금속 장식·폰트·프레임의 정밀한 형태를 확정한 도면은 아니야. 그 부분은 이번에 제시한 스크린샷과 추가 레퍼런스를 기준으로 템플릿별 비교 시안을 마련해 확정하는 편이 좋겠어.
