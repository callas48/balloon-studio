## 통합 원칙

- `public/limbus-data.js`: 기본 데이터·검증·통계. 슬롯/행 ID는 부모 안에서만 의미가 있으며 전역 객체나 다른 부모를 참조하지 않는다. 복제는 공통 deep clone을 그대로 사용한다.
- `public/limbus-ui.js`: 공통 프레임/리벳/기어/카드·이미지·텍스트 렌더. 난수/시간 없는 결정적 렌더, 안정적인 슬롯 hit box, 글자 넘침 목록. UI는 Canvas로 직접 그리며 별도 외부 리소스 요청이 없다.
- `public/limbus-controls.js`: 기본/텍스트·수치/이미지/스타일 4탭, 한 논리 작업 한 Undo, 입력은 기존 렌더 예약과 연동. 이미지는 src별 readonly decode cache이며 로더·출력·비활성 장 썸네일에서 사전 대기한다.
- 전체 이동·크기·회전은 기존 unlocked 이미지 레이어/손잡이를 재사용한다. 기존 프리셋의 고정 동작은 바꾸지 않는다. 일반 레이어 가시성·삭제·복제를 그대로 사용한다.
- 단일 탭은 선택·이동. 더블클릭/더블탭에서 해당 슬롯이 있는 편집 탭을 열고 기존 `miniOpeningRelease` 보호를 사용한다. 텍스트 입력 중 기존 단축키를 가로채지 않는다.
- 일반 페이지 PNG는 기존 흰 페이지 합성. 전용 PNG는 템플릿 자체, 배경 제외, 배경/인물 제외 UI 전용을 지원한다. 이미지 슬롯 빈칸 안내·편집 핸들은 출력하지 않는다. 빈 카드/기프트의 마름모는 UI 장식이다.
- JPEG/PNG/WEBP 사용자 이미지 30MB/1600만 픽셀/직렬화 2400만 문자 상한. 업로드 완료 시 문서·부모 선택과 슬롯별 마지막 요청을 재확인한다.
- 폰트는 기존 공용 및 보유 폰트 관리 기능을 재사용한다. 원작 폰트의 정확한 명칭을 확정하거나 새 폰트를 추출/번들하지 않았다.

## 검증과 한계

`tests/limbus-ui.cjs`: 8종/19변형/여러 비율, 실제 Canvas·JSON 결정성, readonly textarea/select 제약, 입력/Undo·비동기 취소, 0값/12인 통계, 보존되는 목록과 독립 복제, 문서 페이지/넘침, native loader·페이지 PNG·비활성 썸네일, 투명 PNG와 명패의 변환된 hit box를 검사한다.

기존 24종 편집기 audit와 포켓몬 3종/클립보드/컷 경계/더블탭 회귀도 통과했다. 최종 빌드 및 배포 결과는 HANDOFF.md가 기준이다.

실제 브라우저/휴대폰 QA는 미실시. 기존 Worker 앱에는 지원 preview의 dev/static 진입점이 없어 `sites-preview start`가 종료됐으며 서버 설정이나 운영 코드를 QA 우회를 위해 변경하지 않았다. native Canvas 검사와 실기기 동작을 구분한다.

## MSI 작업과의 관계

별도 체크아웃에서 편집기 원본만 변경했다. Electron/MSI·패키지 의존성·GitHub 대상·운영 Worker/스토리지/인증 설정은 수정하지 않았다. 설치형에 반영하려면 이 변경의 클라이언트 파일과 통합 패치를 해당 저장소에 적용해야 한다. MSI 반영·Windows 실기기 검증이 완료됐다고 보고하지 않는다.
